# AMR 运行时绑定：主张、证据与新增验证

日期：2026-09-22。依据最新交接、原始 position paper §4–5、当前引言／运行时／研究议程／结论及 AMR v2 原始代码与证据。范围为已获授权架构内的接口扩展，保留 main 现有材料，不提交、不推送。

## 判断与取舍

继续采用两台 AMR 各一次任务、A 先 B 后登记的 v2 场景。它已经同时具有原始生成源码、严格契约、语义故障对照、离散组合证明和物理记录。当前最直接缺口是证明输入与实际适配器之间的连接。固定工业交接会增加资源交接语义，完整工业编排还会增加计划语言、任务覆盖和证书执行对应；现有证据没有证明这些额外义务能更直接支持本文的语义忠实主张，因此本轮不替换场景。这不否定候选场景的后续迁移价值。

| 主张 | 已有证据 | 缺口 | 本轮新增验证及区分能力 |
|---|---|---|---|
| 接受的原始程序满足明确契约 | 六份历史源码重验；完整有限域；E1 | 原始程序与部署读取之间仍有可信代码 | 复用已接受原始字节与 identity，统一适配器记录实际源码选择，不由 guard 替换选择 |
| 建议影响合法选择但不能扩权 | HOL source_authority、独立 reference、A/B/空建议见证 | HOL Provider 尚是已解析值 | 原始回复经身份与严格解析映射至 Provider；适配器有限迹纳入 S_source，再复用组合证明 |
| 邮箱与锁存满足建议响应 | 一槽邮箱单元测试、六次单决策真实回复 | 邮箱与 source_next 未做组合对应；物理旧驱动只在 t=0 读取快照 | 对完整有限状态和接口输入穷举；错绑定、重复、延迟至锁存之后的回复对照 |
| 错误／缺失建议不能造成自身停滞 | 最多三次 Service 条件授权定理；E4 | 真实适配器的 Service 是否确实不等待建议 | 形式单步对应、有限消息间隔保持核心状态；有服务供给的错误回复突发试验 |
| 证明的事件实际驱动执行 | E3、15 次物理记录、有限 core/source 对应 | 没有统一记录从回复到 source 到协议到动作 | 新物理驱动使用统一适配器，重放保留回复，并核对每一协议事件对应及实际移动／完成 |

## 组件及形式语义

设计时沿用 Forge 式生成—验证—修复留下的 P3-R1 原始控制器，SHA256 为 `9eaa530b58253c1a07c6369882ed59eacb4cfac7dc40850e4100d31f387a47cd`。不追加同题生成来扩大样本量。

新增 `formal-artefacts/amr-runtime-binding/`。运行时接口只有可信 Open、Register、Observe、Validate、Service、Commit、Issue、Apply、Release、Consume 和不可信 Message。Validate／Service 在 pending 为空时原子读取当前持久邮箱并运行原始源码；pending 非空时不重选。Commit／Apply 继续检查当前许可。邮箱请求仅在可信 Open 后激活。绑定为固定、非空字符串 request_id/context_id；不支持同一实例内任务取消、重用或 epoch 切换，新任务必须创建新实例。

形式模型把任意原始文本经解析后的结果表示为 `None/A/B`，身份关系表示为两个相等性布尔值。错误绑定、无效解析映射为静默 Provider None；未 Open 或已占槽时 Provider 不能改变邮箱。模型不把 JSON 解析器的正确性当作已证明结论。字符串／JSON 到这三个类别的联系以 Python 严格解析和边界测试支持，穷举只量化有限抽象域。

证明目标：每个适配器单步对应一个合法 source_next 步；任意有限原始输入序列生成的事件迹属于 S_source；由已证 source_authority 得到参考权限包含。这明确复用既有 P_open、D、K_T 的组合论证，不重新定义安全迹来充当接口。另证任意有限 Message 序列不改变 core，以及空 pending、可用许可下两次 Service 之间插入任意有限 Message 仍可授权。无限消息洪泛挤占调度、真实线程并发和完整物理进展不在此定理中。

## 冻结实验协议

1. HOL 导出全 432 个 core × 6 个 mailbox × 30 个 raw input 抽象转移，逐行比较 Python 执行、原始源码和事件编码。包含不可达状态作为防御性覆盖；不能称全 Python 精化。
2. 固定解析边界语料：合法 A/B、空、畸形、未知 choice、多字段、重复键、错误类型、Unicode、1024 字节边界、超限、嵌套。错请求／错上下文单独覆盖。
3. 固定接口见证：空建议、有效 B、错绑定 B、坏 JSON、有效回复后重复 A、Validate A 后回复 B、旧许可撤销、64 条坏消息后 Service。故障对照只放实验代码：跳过绑定；收到回复后清空 pending 并重新选择；等待建议。分别检查功能／权限／进展，不能把所有故障都报成安全事故。
4. 物理运行四次，最长各 120 s 仿真时间：无回复、重放既有 001 原始回复、坏回复后重放有效回复、首次 Validate/Commit 后到达 B。从区外停止等待位启动，回复时间为明确指定的仿真时刻；不是新增 API 请求或保留历史网络延迟的实时复现。保留全轨迹和输入哈希。没有碰撞、提前释放、权限违例或未决几何检查，且两任务完成才算对应场景通过。
5. 测试／证明失败应修正并保留诊断；不无限增加轮次。全部为本地检查；API 调用数为零，既有 DeepSeek 凭据不读取。

## 证据边界

模型解析抽象、有限 translation validation、真实源码解释执行、参考 plant 仿真是四种不同证据。未证明任意 Python、OS 时限、物理传感器、持续驱动命令的全部行为、连续动力学精化、完整运输条件终止、通用动态 FIFO 或 CKA 方法优越性。活跃 TeX 暂不整合；新增结果需形成候选文字并与旧 I28 口径一致。
