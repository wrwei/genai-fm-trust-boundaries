# AMR 稳定闭环时序：从授权到两任务完成的条件界

2026-09-22。接续运行时绑定、受限提取保持与运输进展义务，本轮在**稳定可用环境**下补齐源码与固定驱动时钟的局部时序论证。结论是：在持续控制／服务、固定观测与命令交付、请求保持登记，以及精确参考 plant 的有界行程服务等明确前提下，两任务第二次 Finish 不晚于 **6,884 个 10 ms tick，即 68.84 s**。这是比上一轮 70.2 s 诊断预算更紧的条件定理，不是任意环境、任意 Python 执行或硬件截止时间。

证据入口：[新增包](../../../formal-artefacts/amr-closed-loop-timing/README.md)、[设计](../../../docs/superpowers/specs/2026-09-22-amr-closed-loop-timing-design.md)、[独立复核](../../../formal-artefacts/amr-closed-loop-timing/review.md)。本轮没有 API 调用、物理重跑、活跃 TeX 修改、提交或推送。

## 1. 时序契约与定理边界

定理时间统一使用 10 ms 自然数 tick；连续物理事件用不早于该事件的首个整数 plant tick 表示。固定驱动契约为：控制／采样周期 5 tick，采样后观测交付 5 tick，命令交付 10 tick；Brake 后源码使用的 1.48125 s 门限在离散控制时钟上首次成立于第 150 tick。环境保持观测可用、任务有效、无人阻塞；控制循环与服务机会持续供给；命令不被执行层拒绝。

在这些条件下，局部界为：

| 义务 | 界 | 含义 |
| --- | ---: | --- |
| 整数事件 tick 到源码可见／BodyClear 到 Release | 9 tick | 任意五相位对齐下的采样与交付；从精确连续时刻起算为 <10 tick |
| Grant 到施加 Proceed | 163 tick | 同时覆盖 `Waiting` 与已经 Brake 的 `BrakeRequested` |
| 施加 Proceed 到物理终点停稳 | 3,100 tick | 上一轮精确参考路线服务前提 |
| 量化后的终点停稳 tick 到 Finish | 169 tick | 观测、Brake 交付、停稳门限及控制对齐；从精确连续时刻起算为 <170 tick |
| 首次授权／前项完成到下次授权 | 各 10 tick | 固定稳定请求与同轮 Validate/Commit 的保守配额 |

由此得到

`10 + (163+3100+169) + 10 + (163+3100+169) = 6884` tick。

最终 Isabelle 定理以八个局部时间不等式为显式前提再作组合，因此没有把最终完成偷偷放入单一前提；但它也没有证明整个 Python 驱动必然满足每项不等式。9、163、169 的调度函数界和释放后授权协议步骤分别在 HOL 中证明；其中 9/169 从量化后的整数事件 tick 起算。3,100 tick 是包含到达量化的精确参考 plant 服务契约。

## 2. 内核检查的源码、提取目标与协议里程碑

[AMR_Closed_Loop_Timing.thy](../../../formal-artefacts/amr-closed-loop-timing/hol/AMR_Closed_Loop_Timing.thy) 导入既有运行时绑定、具体提取制品和进展理论，而非复制它们的结论。Isabelle2025-2 构建成功，16 项审计事实没有跳过证明或 oracle 依赖。

固定源码身份仍为
`9eaa530b58253c1a07c6369882ed59eacb4cfac7dc40850e4100d31f387a47cd`。
内核对八个稳定里程碑计算源码结果，并通过既有普遍保持定理得到提取目标的相同单元素结果：不可用时 Brake；持有预约但尚未停稳时继续 Brake；停稳持有者 Proceed；等待中的新持有者 Proceed；整车清空时 Release；释放后到终点前继续 Proceed；到目标后 Brake；停稳后 Finish。

另一个定理直接使用既有协议的 `Release`、`select`、`Validate` 和 `Commit`：当前持有者有效释放后，若另一请求保持登记、许可新鲜且无阻塞，选择与提交产生另一机器人的 Grant。任意建议值只能在合法候选中选择；当前持有者的请求已经清除，因而不会夺回授权。这是离散授权事实，不是几何清空证明。

## 3. 独立穷举和四条旧轨迹

Python 计时模型与 HOL 分开实现并逐表比较。最终复核覆盖 1,001 个事件 tick，以及 201,402 个 Grant／Brake 年龄／模式组合。穷举最大值为：观测与释放 9 tick，`Waiting` 启动 15 tick，`BrakeRequested` 启动 160 tick，到达后 Finish 169 tick；共同启动界 163 tick 留有三 tick 余量。

实际源码解释器对八个里程碑产生预声明的字面动作／模式，且编码结果等于 HOL 独立导出的源码表和提取目标表。15 项测试包含晚施加 Proceed、晚 Release、缺失目标 Brake、过早 Finish、非法时刻／模式和遗漏计时阶段等负例。

四条运行时绑定物理轨迹原样复用，没有重跑。连续运动片段被独立积分以求整车越过共享区边界和在终点精确停稳的时刻：

| 指标 | 四条轨迹最大观测值 | 对应界 |
| --- | ---: | ---: |
| Grant 到施加 Proceed | 155 tick | 163 tick |
| 物理清空到 Release | 8.069421 tick | 9 tick |
| 施加 Proceed 到实际到达 | 2,978.185425 tick | 3,100 tick |
| 实际到达停稳到 Finish | 151.814576 tick | 169 tick |

四条轨迹均在 58.9 s 完成。首车约 27.3693 s 实际清空、27.45 s Release；约 31.38185 s 到终点停稳、31.4 s 施加 Brake、32.9 s Finish。源码的 `AtGoal` 是 0.01 m 容差谓词，可能早于精确物理到达变真；本轮没有把两者等同，而是单独重构终点停稳。保留轨迹中 Brake 虽然提前请求，10 tick 交付使其在实际到达后才施加。
