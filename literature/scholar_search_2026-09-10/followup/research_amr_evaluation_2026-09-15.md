# AMR-Corridor v0.1：评价协议与证据判据

日期：2026-09-15。状态：研究设计，所有试验待执行。依据[场景规格](research_amr_scenario_2026-09-15.md)。用户确认先做可复现仿真。本协议不报告新LLM性能、AMR仿真结果、完成证明或工业认证。

## 1. 要回答的三个案例问题

这三项为案例评价问题，不替换论文原有三个review问题。

| 问题 | 可反驳的主张 | 如何可能失败 |
| --- | --- | --- |
| E1：设计时验收 | 原始生成监督器满足固定规格，且受检模型保留源码的动作和模式含义 | 检查器接受p，但独立判定得到未授权Proceed、过早Release、遗漏Brake或源／模型不同结果 |
| E2：对应与执行 | 绑定版本／对象及当前物理状态的接受，能避免所选接口错配造成的错误许可 | 在声称覆盖的条件内，实际命令、整车占用或停车轨迹违背被接受的义务 |
| E3：安全与有用性 | 拒绝、制动和回退不会在恢复条件持续成立时无故阻止任务；建议在合法分支中有可见作用 | 全部运行靠停车维持安全；合法恢复不发生；建议不影响任何选择；或安全执行了错误任务 |

不预设必须证明LLM优于手写控制器；也不预设每次自然生成都会失败。真实模型没有出现某类错误，应如实记为本协议下未观察到，人工注入只说明机制对指定错误的区分力。

## 2. 独立判定及记录边界

1. 冻结任务真值、允许的顺序集合和站点规格，再生成源码。测试答案不提供给生成器，运行时不向控制器提供plant真值。
2. 控制器的源码解释、验证模型提取及参考规则判定分开实现；至少一个反例应能让任意两者不一致。形式化结果需要报告公理／admission、版本和源文件身份。
3. plant依据实际交付的指令和动力学推进，不调用验证器的停车距离函数。连续碰撞判定使用独立的实体轮廓和扫掠算法，不仅检查离散输出帧。
4. 对碰撞判定准备“两个采样帧均无重叠、帧间发生穿越”的已知几何见证；判定器必须发现。对停车准备独立解析运动轨迹；核对数值步长收敛不能代替模型真实性。
5. 记录任务、候选和修复原文；model_id/version、提示哈希、解码参数、请求时间、失败／超时、全部响应；源码、规格、提取器、适配器、执行器和参数哈希；每次观测、接受／拒绝、指令交付、真实位置／速度、预约变更及任务结束原因。
6. 实验注入的隐藏定位误差／制动失效可被离线评估器发现，但运行时不因此自动知道。分别记录assumption_violated与assumption_detected，未检测的失效不能写成安全机制成功识别。

## 3. 首批场景与故障目录

以下是预先设计的测试情形。表内“应”是验收要求；不是实际结果，失败见证能否实现须在plant建立后验证。

| 编号 | 设置及改变 | 主要观察 | 分组 |
| --- | --- | --- | --- |
| C01 | 两车各一次任务、无人员；分别提供合法A／B先行建议 | 两种顺序可区分、轮廓不冲突、两任务完成 | 正常／作用性 |
| C02 | 同一目标的三种任务表述，含工位别名；另设真正无法唯一确定目标的请求 | 等价请求的允许结果集合一致；歧义请求Clarify；任务语义与运动安全分别计分 | 真实LLM任务 |
| C03 | p在发现人员时仍Proceed，或合语法地一直Brake | 原始候选拒绝；经过回退后的安全不能把它改记为合格 | 人工候选＋自然错误另列 |
| C04 | 先前Brake分支与后续Proceed分支同时可满足，提取器漏前序否定 | 源／模型比较应拒绝错误对应；模型自检通过本身不充分 | 翻译故障 |
| C05 | A车头已出Z但车尾仍在Z；缺陷适配器报告clear，B等待进入 | 独立物理占用与模型占用不一致；正确Release应等待整车清空 | 几何对应故障 |
| C06 | 观测包含另一个robot_id，或米与毫米／左右出口混淆 | 类型／身份不符拒绝；语义错误若未被发现，plant判定必须暴露，不能承诺哈希自动检测它 | 适配故障 |
| C07 | 在已知固定边界前逐步接近，比较完整停车包络与遗漏反应时间／速度误差的包络 | 允许继续／允许初始状态的集合差异，实际停车位置及是否越界 | 物理条件 |
| C08 | A停在Z内，心跳暂缺或预约计时到期 | B仍不能进入；恢复后凭位置清空，不凭时间清空 | 协议／失联 |
| C09 | 旧Proceed到达晚于新Brake；或建议引用的任务／地图版本变化 | 旧指令不得覆盖Brake；拒绝原因、实际执行顺序及停车轨迹 | 交付顺序／版本 |
| C10 | 行人在可停车距离外被检测，随后横穿H并离开 | BrakeRequested到Stopped有非零时间；条件有效时停在H前，恢复后完成 | 条件内人车交互 |
| C11 | 人员在AMR已进入H时出现，或遮挡至不可停车距离内 | 如实报告最近距离／碰撞和前提失效；不以“已经停车”断言避免碰撞 | 保证域外边界 |
| C12 | 永久阻塞与暂时阻塞成对比较；再单独改变实际制动、定位误差或执行延迟 | 区分合理未完成、无故不恢复、条件内缺陷与条件外失效 | 进展／假设压力 |

C07不能把一个一开始就无法停车的状态用于宣称完整方案必然安全：对于该状态，正确结果是拒绝作出停车保证并执行尽可能的制动。闭环方案间比较应从同一已确认可行的初始状态开始，检验速度／继续许可是否维持必要条件。

参数压力先单因素改变，使用[参数表](research_amr_parameters_2026-09-15.json)中的within、boundary和outside_assumption三类；随后再做少量组合失效。边界外仍报告全部结果，但不与条件内缺陷合并成一个“安全成功率”。

## 4. 对照与消融

| 组别 | 设置 | 作用和解释限制 |
| --- | --- | --- |
| R：手写参考 | 手写正确监督器＋同一运行时建议输入＋完整当前状态与物理检查 | 强基线，校准环境可完成性；不靠去掉传统方法的安全能力制造优势 |
| G：生成监督器 | 固定规格验收后的p＋与R相同的运动控制、预约、建议和安全层 | 研究生成与接受；若生成p的行为与R相同，这也是有效结果 |
| G-S | 相对G，仅禁用源／模型对应验证；其他验收和回退保留 | 定位错误提取可否导致错误接受；不保证一定引发物理事故 |
| G-B | 相对G，仅破坏一项状态／动作绑定，如整车清空或过期命令检查 | 测量指定连接缺失的后果；这是自构造消融，不命名为某外部系统 |
| G-T | 相对G，仅在停车判据中漏掉一个时间／误差项 | 检验模型条件与实际运动的差异；不同时改变制动器或任务 |
| R-Stop | 始终请求停车，保留相同plant | 退化参照，展示仅统计零碰撞会误导；不是主要竞争基线 |

G-B每次只使用一种故障，不把多个不同缺陷合成一个组。被测适配器的故障应在其证据生成之前注入，检查能否发现其错误语义；若只在部署后改文件而被hash拒绝，证据仅支持身份检查，不支持语义正确。

对组件检查采用相同候选／快照／外生事件作配对重放。对任务完成必须重新闭环运行：不同拒绝或停车会改变后续观测与LLM输入，不能用同一段固定动作录像推断闭环效用。场景中的外生事件由仿真时钟或事前规定的相对触发条件驱动，并记录采用哪一种；禁止观察方案表现后移动行人时刻。

## 5. 真实LLM试点的规模和顺序

### 5.1 先验证环境和判定器

先实现R和R-Stop，在C01、C05、C07、C08、C10、C12上确认：正常任务可完成；至少一个错误对应确实可被独立判定发现；停车与已停稳不同；永久阻塞不会被错误计为应当完成。不能先反复调整模型提示，让环境看起来能通过。

### 5.2 设计时生成试点

首轮建议一个真实模型、6份站点规则包，每包3种等价表述，每种2次独立采样，共36个初始候选；每个最多2次基于真实失败反馈的修复。最多108次生成／修复调用，仅为试点上界，不含运行时建议。提示开发另用2份开发规则，不进入这36个候选的评价。

六包覆盖：基础互斥；人员触发停车；暂停后的重新许可；任务／策略版本绑定；整车退出释放；前述义务的组合。每包明确目标义务，只有组合包完成所有适用验收后才可进入完整G组闭环。单义务包不因没有要求其他义务而被记为全系统合格。

修复可以改变候选，不能改变规则包或接受器；超时、解析失败、不支持特性及拒绝均保留。按候选记录初始／修复后的接受和独立判定，不把108次调用当成108个独立样本。6种规则及表述相关，36个候选也不是36个独立工业任务。

### 5.3 运行时建议与闭环

运行时试点准备12份任务请求：6份允许选择唯一先行顺序、4份允许两种顺序、2份存在必须澄清的歧义。认可规则及可观察事实决定允许集合，开发提示不使用这12份测试文本。任务排序可参考文本，安全条件来自独立状态输入。

每个请求做2次独立建议生成，共24份初始建议；这不是包含后续重新建议的完整闭环调用上限。后续建议的触发规则、每episode上限、超时策略另在真实调用前冻结，不能按运行表现临时追加。固定记录缺失、迟到和错误绑定处理。合格生成监督器按预先规定的候选编号选择，不按闭环表现挑选“最好”程序；首先保留全部合格组合包候选的检查结果，再以编号最小者运行首批闭环。若无组合包通过，报告该结果，用R完成物理环境评价，不能偷偷改为手写p后仍标记G。

正式的模型间比较与样本量在试点后按研究主张和任务间变异确定；新增测试集须在调参前冻结。36个候选和少量闭环无事故不支持极低失效率、工业可靠性或统计上的普遍优势。具体model_id/version、解码参数和提示必须在调用前登记；本轮只制定协议，没有调用授权之外的服务。

## 6. 必报结果

| 维度 | 指标及分母 |
| --- | --- |
| 原始候选质量 | 独立判断不合格数／可解释候选数；解析失败另列 |
| 错误接受 | 验收通过但独立判断违规的候选数／所有验收通过候选数；分母为0记不可估计 |
| 语义对应 | 源／目标动作或模式不一致的已检查输入对数、具体见证及检查域 |
| 物理安全 | 有碰撞的episode数／执行episode数；车车、人车、墙体分别列；最小实体距离、越界与余量不足另列 |
| 安全且成功 | 全程无规定违规且正确目标完成的episode数／全部任务episode数；包括失败与超时 |
| 任务与恢复 | 正确工位／允许先行顺序、澄清正确性、解除阻塞后的恢复延迟、完成时间、未完成原因 |
| 干预与负担 | 原始提议拒绝、紧急制动、无效恢复、合法提议误拒；对应可判定集合及人工／模型判定来源 |
| 成本 | 生成／修复调用、tokens、核验时间、运行时建议延迟、安全线程时序；仿真时间与墙钟时间分别记录 |
| 保证前提 | 条件内／边界／条件外结果，已知或未检测的假设失效及其首次发生时刻 |

不得把制动次数越多自动解释为更安全，也不能把合法但低效的建议计为碰撞。终态正确不能抹去曾经发生的物理违规。

## 7. 进入正文的判据

最小可交付证据应包括：一个可复建的正常闭环；一个已检查的源码／模型错配；一个逻辑许可与物理条件错配；一组暂停／恢复／无法恢复的区分；真实LLM的原始输出和接受记录。若其中某一项未获得，则在论文中明确降为设计或模型说明。

是否需要更高逼真仿真，取决于当前结论是否对自建plant过于敏感：例如缩小时间步即改变主要结论，或错误只能在某个手写积分器中出现。届时优先复核plant和独立积分／几何实现，再考虑完整机器人栈；不得把换渲染器当成独立验证。

首版达到这些判据后再决定正文中bridge与AMR的篇幅。没有新理论或实验结果时，不改写当前已编译候选中的完成声明。
