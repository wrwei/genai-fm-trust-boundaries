# AMR 源码提取语义保持：从有限重验到受限剖面定理

2026-09-22，继续上一轮[运行时绑定](research_amr_binding_results_2026-09-22.md)。本轮补强设计时接受所依据的源码—模型联系，没有更换案例、控制器、契约或运行时架构。实现与证明入口：[amr-extraction-faithfulness](../../../formal-artefacts/amr-extraction-faithfulness/README.md)。

## 1. 为什么本轮先做这一段

原始 position paper §4 的技术中心是验证对象与实际制品的语义忠实，并提出先对受限控制剖面证明行为保持。此前 AMR 每份源码的 1,824 输入穷举和 E1 故障对照支持具体对应，但没有给出该 AMR 提取结构的普遍定理。上一轮进一步连接了运行时接口与实际记录，仍未替代设计时的这一义务。

完整运输终止需要独立论证路径推进、制动、阻挡恢复与服务供给；简单假设“获准的车最终完成”再推导完成会把关键问题留在前提中。因此本轮先完成现有代码已经足以精确定义、且直接对应文章技术中心的提取保持，再维持物理进展的既有证据边界。

旧 bridge-profile 的 flatten_correct 针对另一种带末尾 Return 的抽象语法，不包含当前 AMR 的后缀栈执行、NOT 消去、无匹配观察或原始 AMR 字节绑定。本轮不是重命名该旧定理。

## 2. 已完成的形式结果

Isabelle2025-2 构建成功，主理论仅导入 Main。源语言由布尔常量、事实、not、变元数 and/or 与按优先顺序的规则组成；目标语言为 PUSH、LOAD、NOT、AND n、OR n。提取器保留实际 Python 的两个细节：表达式 not 会消去尾随 NOT；规则优先级屏蔽则对每个更早原条件直接追加 NOT、AND 2，不使用这项优化。

主要定理是：

```text
对任意表达式 e、总布尔环境 ρ 与原栈 s：
run_code(compile(e), ρ, s) = Some(eval_expr(ρ,e) :: s)

对任意有限有序规则表 rs 与总布尔环境 ρ：
target_results(ρ, extract_rules(rs)) = result_list(source_result(ρ,rs))
```

第二个等式保留目标输出列表，不用集合去重掩盖额外启用分支。首个满足规则的 action 与 next_mode 原样保留；没有匹配时，两边分别是无结果与空列表。表达式证明允许任意原栈，因此涵盖嵌套表达式与 NOT 优化对既有栈的影响，而非只检查空栈上的若干表达式。

性质传递分为两种：若 source 已有输出，则目标输出性质可传递给它；若还要建立存在输出，必须增加目标非空前提。保持定理本身既不验证需求充分性，也不保证规则完整。手工构造的优先级遗漏、缺失否定及无匹配见证均在 HOL 中检查，不是模型生成错误率。

## 3. 与实际生成制品的绑定

本轮读取六份历史原始回复，保留五个不同字节身份及重复关系，不增加生成样本。对每个身份分别导出源 AST 与实际 Python `extract_model` 产生的目标指令表，得到十项结构相等性证明（选择／动作各一项），并分别实例化为任意环境下的行为保持推论。部署身份仍是：

`9eaa530b58253c1a07c6369882ed59eacb4cfac7dc40850e4100d31f387a47cd`。

该身份同时与 v2 选择记录、原始保存字节及上一轮 runtime adapter 的 SOURCE_ID 对应。所有具体等式由 Isabelle `code_simp` 检查；主定理与具体绑定的依赖审计均没有跳过证明或 oracle。

[独立复核](../../../formal-artefacts/amr-extraction-faithfulness/review.md)另行解析20个HOL源／目标定义，核对65条源规则及原始AST、payload、指令、身份与哈希，未发现未解决问题。5项导出测试通过；快照再生成一致，上一轮运行时证据包36项文件全部保持原样。

另外冻结19个表达式结构，覆盖双／三重否定、七层否定、嵌套逻辑、重复原子和变元数边界。13个属于可解析语法；6个是零／一元算子的构造器边界，不能冒充文本解析器可输出的语法。其实际 Python 编译结果与 HOL 逐项绑定；每个结构在8个布尔环境下的源／目标解释器结果也经 HOL 核对，共152个成对求值检查。这些是实现联系样例，不是普遍定理的实验替代，也不是152个独立模型样本。

## 4. 没有被悄悄改变的验收含义

Python 源解释器在无匹配时抛 `ValueError("no matching ... rule")`，不是返回 None。HOL 用 None 表示这种特定无结果观察；导出测试只允许该异常归约，其他输入／解析错误继续抛出。旧验收器将无匹配视为不完整及对应失败，其规则完全保留。因此，部分语义保持没有把拒绝的程序变成可部署程序。

同样，五个不同源码都忠实提取，不表示它们都满足 v2 的建议响应契约。历史结论依旧是旧契约6/6、增强契约1/6；提取忠实与功能正确是两个义务。

HOL 栈顶位于列表头，Python 栈顶位于列表尾；任意初始栈结果采用对应表示。HOL 明确拒绝操作数不足，而 Python AND/OR 切片对某些损坏字节码不会报错。本轮只连接良构生成代码，不能宣称两个执行器对任意损坏指令流等价。
