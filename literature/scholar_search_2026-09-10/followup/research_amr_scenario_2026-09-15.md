# AMR-Corridor v0.1：厂区窄通道的通行许可、保护停车与恢复

日期：2026-09-15。状态：**已完成首版研究设计，未实现、未仿真、未证明。** 用户同意细化工业移动机器人场景，并明确“目前没有，先按可复现仿真设计”。具体参数是本次提出的仿真初值，不是实机数据或标准规定。

本文件是AMR场景设计入口；[评价协议](research_amr_evaluation_2026-09-15.md)规定如何检验，[参数表](research_amr_parameters_2026-09-15.json)固定首版数值。既有[bridge结果](research_case_results_2026-09-15.md)继续保留，AMR不继承其计数、定理或通过状态。论文仍为critical review，新增案例尚不进入已完成实验的叙述。

## 1. 选定的任务与危险过程

两台低速物流AMR运送普通备件，分别从窄通道两端申请通过；窄通道中部有人员横穿区域。运行区域、固定路线和交通管理规则已知。自然语言任务给出工位、任务优先级和作业通告，LLM提出任务解释和通行次序。AMR执行时必须处理人员出现、信息迟到、状态变化及恢复。

首版任务示例：“将备件送到装配工位。两台车都在等待时优先处理已确认的缺料任务；人员横穿期间暂停通行，人员离开后继续。”缺料任务的目标和合法优先关系由独立任务标注确定，不能由同一个LLM自评。

**贯穿全案的问题：控制器已经获得通行许可，为什么仍可能不能安全执行？需要哪些证据才能把逻辑上的许可对应到机器人此刻的位置、运动和可用制动能力？**

首版只使用一条受控通路。先不实现任意绕行规划、抓取、货物装卸、视觉识别网络、多资源调度或整座仓库优化。此前举例的“东侧封闭，改走西侧”暂不进入首版；两个可区分的运行时合法后果是让A或B先通过，不为增加LLM功能而新增道路系统。

## 3. 正常任务与受扰动任务

正常任务按以下顺序运行：

1. A和B在等待位登记不同的mission_id。任务解释形成带task_revision的建议；明确的歧义进入Clarify，不任意选一个任务。
2. 两个当前合法申请都可服务时，采纳有效的先行建议；建议缺失则使用固定A先B后的次序。首版每车一次任务，无持续到达或K=2无界公平主张。
3. 预约管理器原子授予唯一owner，并绑定mission_id、reservation_id和当前策略版本；仅授权请求不意味着车辆已经进入。
4. 控制器提出Proceed，经当前状态检查后交给固定运动控制器。安全监测按自己的周期运行，不等待LLM答复。
5. 人员出现且机器人尚可停在横穿带外时，执行制动；状态先为BrakeRequested，经制动执行及停稳依据确认后才能记为Stopped。
6. 人员阻塞消失、观测恢复且当前继续条件成立时，控制器允许恢复。此前迟到的Proceed建议不能直接恢复运动。
7. 新鲜观测的整车不确定轮廓完全离开Z，且出口版本／方向匹配后，才释放预约。随后服务另一辆车。
8. 到达指定工位并停稳才记任务完成；仅离开Z不等于完成运输。

停止在Z内的车仍占用Z。令牌时间过去、心跳中断、发出停车命令、模型进入Done状态，都不能单独释放Z。首版不实现超时自动回收；失联导致保留占用并停止另一车进入，恢复后再依照当前位置处理。任务已取消但车辆仍在Z内时，同样保留占用。

## 4. LLM分工及不可越过的接口

| 层次 | 输入／输出 | 角色和接受依据 |
| --- | --- | --- |
| 设计时LLM | 固定的站点规则、类型接口、正反需求例子 → 受限监督控制器p | 生成模式转换和通行选择逻辑；对原始p验收，不能用运行时兜底冒充p合格 |
| 运行时LLM | 任务描述、作业通告、带版本任务摘要 → Prefer(A/B)、继续建议或Clarify | 理解任务及提出建议；不写速度指令、预约记录、观测真值或制动参数 |
| 认可规格与任务判定 | 作者事前定义的规则、任务目标与允许选择集合 | 验收标准固定，生成／修复不能悄悄弱化；自然语言忠实单列任务评价 |
| 预约及输入适配 | 传感包、任务版本、动作提议 → 当前可执行意图 | 检查对象、方向、时间和身份；LLM输出不能改写可信状态字段 |
| 固定运动控制与安全监测 | 当前观测、路径及受控意图 → 运动／制动 | 实现低层运动；其证据不归功于LLM生成的监督控制器 |
| 仿真plant与独立评估器 | 实际执行指令 → 真实运动及事件 | 评估器读取完整plant轨迹；控制器只见传感包，不见用于评分的真值 |

任务解释正确和运动安全分别计分。一辆车可以安全地完成错误任务，也可以因为一直停车而不碰撞；两者都不能计为安全且成功的任务执行。

监督控制器p包含一个纯通行选择函数和一个逐车纯模式决策函数，均使用无循环有序分支：

- 选择函数返回Select(A)、Select(B)或Defer，只提出预约候选；实际owner只能由预约管理器改变。
- 模式函数返回Request、Proceed、Brake、Resume、Release或Finish及下一逻辑模式；返回值是意图，不直接写plant或预约表。
- 固定模式集为Idle、Waiting、Traversing、BrakeRequested、Stopped、ResumePending、Done。每个模式最多8个有序分支，总分支最多32；精确字段名和序列化语法在实现前依此类型表冻结。
- 可读字段包括OwnReservation、ObservationUsable、PedestrianBlocked、BoundaryStopAdmissible、BodyClearOfZ、Halted、AtGoal及有效建议。数值几何转换在有类型的适配层中定义，不能把这些布尔字段默认当成物理真值。
- 禁止外部调用、任意赋值、修改阈值、修改规格、隐含单位转换或直接发速度命令。不支持的源码明确拒绝，不自动改写成另一程序后记原候选通过。

现有HOL有序分支证明可作为扩展模板；它的动作类型、无状态求值和导入范围与本案不同。新动作、模式迁移、文本解析和执行对应均需另行说明或证明。

预期模式关系如下，具体布尔条件均指当前有效输入；模式标签本身不产生物理事实：

| 起点 | 条件／动作 | 目标及不变量 |
| --- | --- | --- |
| Idle | 有已解析任务，Request | Waiting；仍未拥有Z |
| Waiting | 获得本任务预约且当前进入条件成立，Proceed | Traversing；由实际轮廓另记进入事件 |
| Traversing或ResumePending | 检测到阻塞／不可用观测，Brake | BrakeRequested；保留预约 |
| BrakeRequested | 持续制动达到模型停稳依据 | Stopped；不能用发送Brake代替这一迁移 |
| Stopped | 阻塞解除、任务／预约有效且重新检查通过，Resume | ResumePending；执行端再接受当前Proceed才运动 |
| Traversing | 整车已清空对应出口，Release | 释放预约；仍须继续到工位，不能立即Done |
| 任意适用模式 | 已在目标工位、Halted且无未清空占用，Finish | Done；任务完成和预约释放分别有依据 |

安全阻塞条件优先于建议采纳。建议缺失采用固定通行次序，正常服务仍可继续；控制器制品无效或p产生不合法意图，则执行器请求Brake并保留真实占用。这两种“回退”分别记录，不能把不可信p继续运行说成建议缺失时的正常回退。未获预约的停车车必须重新Request，不能仅由Resume恢复穿越。

## 5. 数据、时间和状态绑定

一次观测至少含robot_id、sample_id、sample_time、frame_id、位置／速度及其区间、已知障碍观测、map_revision。任务输入含mission_id和task_revision。建议含advice_id、引用的task_revision、相关观测号、建议值及接收时间。运行时默认有效期2秒是建议采用策略，不是制动截止时间。

决策提议绑定robot_id、mission_id、reservation_id、controller_hash、spec_hash、adapter_hash、map_revision、引用观测号和advice_id。解释器输出与提交的意图采用同一份不可变记录，不能在检查后重新让LLM生成执行参数。

当前状态检查由单一事件调度器串行处理，并记录明确顺序：观测接收／任务更新 → 验证提议与预约变更 → 发送指令 → plant按实际交付时刻执行。若同一时间戳有多事件，使用预先固定的事件优先级和递增事件号；不依赖系统线程碰巧先执行谁。

高频物理观测采用age与不确定区间处理，不要求每次新传感帧都使整个任务建议失效。mission、map、spec、controller或预约身份改变则使相关旧提议失效。过期建议可以被忽略，是否继续运动取决于当前执行条件，不能把“等待新LLM”设为安全监测或必要控制服务的前提。

“提交检查原子”只针对本地软件状态。发送到执行器存在延迟，需要序列号、有效期、单一指令通道和执行器拒绝过期指令。Brake具有优先权：迟到的旧Proceed不能覆盖更新的Brake；安全监测对指令延迟的界仍单列。

## 6. 物理模型和停车条件

首版使用固定路线上的连续运动：沿程位置s满足ds/dt=v、速度满足dv/dt=a，v不小于0；制动达到0后保持，不因积分越界倒车。朝向按路线转角处理；二维位置和实体轮廓由路线、朝向及跟踪误差生成。参考计算与plant实现分开，不能让plant直接调用安全检查器的停车公式来生成“安全轨迹”。

提议初值：速度上限1.0 m/s、向前加速度上界0.5 m/s²、有效制动减速度下界0.8 m/s²；位置误差0.05 m、速度误差0.05 m/s、几何余量0.20 m。观测年龄上限0.10 s，安全监测周期0.05 s，计算界0.02 s，传输到制动起效界0.08 s，总反应界0.25 s。所有值均为合成实验参数，之后可依平台标定替换并重验。

对直线接近的固定禁止边界，令v_u=max(0,观测速度+速度误差界)，T为从观测时刻到制动开始的保守总时间，a_+为该时间内的向前加速度上界，b_-为制动减速度下界。以观测时刻估计的车头到边界距离d_hat为基准，拟采用充分条件：

`d_hat >= v_u*T + 0.5*a_+*T^2 + (v_u+a_+*T)^2/(2*b_-) + epsilon_x + margin`。

位置误差只计一次，车长已通过“车头”定义进入d_hat。采用观测时刻车头时，T必须包含观测年龄；不能用当前估计车头再重复计同一位移，也不能忽略观测时刻到现在的运动。公式保守地不利用速度上限截断反应期加速。

该式来自分段有界加速／制动的运动学包络，只是本案拟证明的充分条件，不是ISO条文或现成实机安全保证。在上述初值、观测速度1.0 m/s下，数值约为1.391 m；单用v²/(2b)会漏掉误差和反应期。设计数值核算见[核查记录](research_amr_design_validation_2026-09-15.json)。

实现时须区分立即制动的可行条件和允许再运行一个监测周期的条件：后者必须预留下一次监测、通信和制动的时间。不能等到距离已经小于“立即制动也能停住”的界才开始制动。观测中断时，从最后一个被接受的状态到制动起效的最坏时间同样计入；未知位置没有自动变安全。以上持续保持条件是后续证明和闭环核查的任务，单次公式成立不能替代闭环不变量。

停车命令本身不等于停稳。Halted的模型依据是有效制动持续时间足以使速度上界降到0，并继续保持制动；如果制动下界或执行确认失效，不能仅凭逻辑模式推断Halted。实机阶段须另有可支持的停稳判定。

BodyClearOfZ要求新鲜位置的不确定整车轮廓与Z之间满足退出余量并位于对应出口侧。未知位置保留占用，不能把unknown映射为clear。仿真评分用真实整车轮廓另算占用，不复用控制器的BodyClearOfZ函数。

### 人员横穿的条件必须单列

人员不服从AMR预约；车车互斥不能推出人车避碰。首版人员沿H横穿，停在H外且保持余量的AMR可与该限定路径分离。

对于“检测到人员后停在H前”的物理主张，前提包括：首次有效阻塞信息到达时尚未进入H且有足够制动距离；观测／时延／制动界成立；人员身体运动保持在所声明的横穿带内。机器人已在H内、遮挡直到制动不可避免或人员偏离该带时，不在这个停车引理的适用域内。

正常闭环评价仍包含人员在机器人通过期间接近的事件，并记录实际碰撞及最小距离。首版没有普遍的人体可达集或双向避让证明，不能把全部仿真无碰撞升级为任意行人轨迹保证。若要扩大保证域，需要增加可达集／通行时间间隙分析或有依据的联锁设施模型，不能直接添加“PedClear=true”假设消去问题。

## 7. 危害、义务与所需证据

| ID | 危险／错误接受 | 拟检查义务 | 证据对象 |
| --- | --- | --- | --- |
| H1 | 整车未出Z却让对向车进入 | 唯一预约＋整车清空确认＋正确物理占用映射 | 离散协议性质、几何连接、完整plant轨迹 |
| H2 | 逻辑已Brake或Stopped，实体仍越过H边界 | 停车距离含误差和反应期；Halted区分命令与实际状态 | 条件停车包络及执行时间记录 |
| H3 | 旧观测／旧任务的允许结论用于当前动作 | 按依赖验证版本和新鲜度；当前几何重新检查 | 提议—接受—交付链和交错见证 |
| H4 | 源程序选择Brake，模型或执行器却使用Proceed | 有序分支、动作及模式转移对应，单位／方向正确 | 原始p、提取模型、适配器、实际指令的分别比较 |
| H5 | 一直停止或频繁拒绝导致任务无法完成 | 清除阻塞且前提持续有效后可恢复；安全和完成分别验收 | 原始控制器义务及闭环任务完成记录 |
| H6 | 较弱制动、较大误差或人员近距进入使包络失效 | 前提账本区分在线可检查与仅可离线知道的条件 | 边界和越界实验；不得把未知假设失效写成已检测 |
| H7 | 符号任务正确但实体运到错误工位／顺序 | 自然语言意图到任务对象的独立判定 | 隐藏的任务标注、合法选择集合、真实终态 |

允许讨论的证据分为：规格与任务例子的认可；受限源码／AST／模型对应；协议模型性质；条件物理停车结果；仿真中的实现与效果观察。每层都可单独失败。暂不声明组合定理已成立，不预设必须由多个不同验证器完成。

进展只在任务仍有效、阻塞最终解除、控制持续得到执行、预约持有者可完成退出及无永久硬件故障等前提下研究。120秒仿真未完成是超时观察，不是饥饿定理；无限无Exit或永久人员阻塞时安全停车是合理结果。

## 8. 仿真路线与停止扩展的条件

| 路线 | 本次决策 |
| --- | --- |
| 带时间和连续运动的二维确定性模型 | 首选。显式plant、观测延迟、指令队列、机器人轮廓和独立效果判定；可无图形重放 |
| ROS 2／Gazebo或其他完整机器人栈 | 作为后续交叉验证。先确认首版证据链，再固定平台版本和适配接口；当前未安装或选定发行版 |
| 高逼真视觉或实机 | 需要新的标定及环境证据。用户暂无设备，本轮不将其列为已具备条件 |

二维仿真仍必须有实际plant闭环，不能只把离散Grant显示为动画。安全评分要检测时间步之间的扫掠相交或使用有依据的连续碰撞界，不能仅检查0.01秒输出帧。有限状态证明必须给出连续状态到离散谓词的关系；数值分箱本身不是抽象正确性证明。

## 9. 与原研究及已有工作的关系

K1由原始候选和回退分开验收体现；K3由源码到模式、观测到几何谓词两种对应体现；K5由当前提交和真实执行时刻体现；K6由停车前提及任务完成体现。K2/K4/K7的文献综合继续由原稿承担，不扩展一个案例去验证全部review结论。

原bridge提供义务覆盖与有序分支解释的基础。是否能建立AMR某投影到bridge的模拟关系，需要检查额外模式、连续状态、时间和输入身份；当前没有此关系定理，不把65/13/1或31×3计数放入AMR实验表。

工业语境参考ISO 3691-4:2023公开范围，其列举包括AMR；本轮仅核公开范围与版本状态，未读取全部标准，也不声称符合或认证。Nav2 Collision Monitor说明已有利用传感输入在规划器之外干预的机制；AESOP已有为慢LLM推理保留恢复选择的研究。因此，本案的贡献目标是可核查的生成—模型—执行连接及边界评价，不能把“LLM＋独立安全控制”本身称为新架构。来源与读取深度见[来源记录](research_amr_sources_2026-09-15.json)。
