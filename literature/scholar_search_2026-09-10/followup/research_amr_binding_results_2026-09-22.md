# AMR 案例设计与运行时证据连接：新增结果

2026-09-22。延续[交接](../../../docs/handoffs/2026-09-22-case-design-and-experiments.md)确认的架构，按[本轮设计](../../../docs/superpowers/specs/2026-09-22-amr-runtime-binding-design.md)完成适配器、形式可行性核查、有限实现对应与四次物理执行。完整入口为 [amr-runtime-binding](../../../formal-artefacts/amr-runtime-binding/README.md)。原 AMR v2 源码、理论及历史记录未修改；活跃 TeX 未更新。

## 1. 稳定的案例判断

继续 AMR v2，依据是论文的技术中心与缺口位置：原始 position paper §4 要求验证对象与实际制品的语义联系，§5 把建议无权限作为部署时延伸；当前综述引言、运行时与研究议程也围绕局部结果如何支持系统主张。AMR v2 已有生成源码、功能契约、模型与物理谓词故障对照、具体交错迹组合证明和物理运行。本轮最有区分力的新增工作是补强从输入到执行的连接。

固定工业交接与完整任务编排仍是候选，尚无已验证证据证明其新增范围能更直接支持上述主张。这里没有把直接状态机证明的存在理解为 CKA 无用，也没有把采用交换律当作更换案例的理由。继续 AMR 是当前证据支持的范围判断，不是认定 AMR 足以验证全部研究议程。

## 2. 新增的完整连接与证明

设计时保留原始受限控制器源码 P3-R1，SHA256 `9eaa530b58253c1a07c6369882ed59eacb4cfac7dc40850e4100d31f387a47cd`，沿用已有生成—验证—修复及有限接受证据。新增适配器构造时检查具体 SourceController 类型、原始字节哈希和已验身份；Validate/Service 在 pending 为空时实际调用原始源码。guard 没有另行提供替代选择。

运行时增加可核查的统一事件入口：可信 RequestAdvice 开启固定任务邮箱；任意回复经过原始严格解析与 request/context 相等性检查，得到 Provider None/A/B；可信选择、提交与动作进入既有协议。每步保留 raw_input、抽象 event、完整 before/after 与实际源码输出。新物理驱动使用这些事件执行实际协议及参考 plant，不再用独立的初始邮箱快照来代表全部后续决策。

新增 Isabelle2025-2 会话实际构建成功，七项目标无跳过证明或 oracle 依赖：单步对应、任意有限输入迹可接受、S_source 包含、P_open/D/K_T 组件嵌入、参考权限包含、任意有限消息序列不改变 core、条件下两次服务授权。权限定理通过既有 `source_authority` 复用已有组合链，不在运行时逐建议调用证明器，也未新建完整 CKA 代数实例。

这里“原始输入”在 HOL 中仍有明确抽象：任意身份归约为两个相等性布尔量，任意文本归约为解析结果 None/A/B。证明量化所有这些抽象输入序列；它没有证明 JSON 解析器或 Python 语义。

## 3. 主张分开验收

| 义务 | 本轮结果 | 能支持什么 |
|---|---|---|
| 形式接口—实现对应 | 432 core × 6 mailbox × 30 input = **77,760** 转移逐行相同；包含输出事件与实际源码选择 | 完整有限适配器域的 translation validation；比此前 core-only 检查多覆盖邮箱与接口事件 |
| 解析联系 | **24** 固定边界输入通过，包括转义键、重复键、1024/1025 字节、无效 Unicode／类型 | 当前 parser 的具体边界证据，不是任意字符串的证明 |
| 建议响应 | 合法 B 选 B；缺失／错绑定／坏 JSON 回退 A；重复回复不覆盖；锁存 A 后到达 B 仍提交 A | 建议有效时有用，不能回写已经验证的选择 |
| 权限包含 | 适配器有限迹嵌入原组合，继承独立 reference 包含；撤销许可后 Commit 不授权 | 当前模型状态下的离散权限保证 |
| 条件进展 | 空 pending、有效许可与请求下，两次 Service 之间任意有限消息不妨碍授权；64 条错绑定消息见证之后仍授权 A | 建议本身不构成等待条件；仍要求服务供给 |
| 实际执行联系 | 四次新驱动运行与逐迹审计均通过 | 当前参考 plant 与有限时段内的执行证据 |

十一条有界机制见证均符合预先列出的期待。其中三项故障是实验手工构造：跳过绑定让旧请求 B 改变选择；在晚回复时清空 pending 导致原已锁存 A 变成 B；等待空建议则阻塞两个已安排的服务机会。前两者破坏原始输入到模型的对应与功能契约，授权本身仍合法；第三者保留已发生有限迹的安全包含但没有服务进展。不得把它们都报成安全事故或自然生成错误率。等待的永久性一般见证仍由既有 HOL `wait_forever` 提供，本轮两个机会的实验自身只是有界观察。

独立初审发现构造器曾允许任意 source 对象，使无建议时选择 B 可以通过安全检查却偏离 source_next。已增加固定类型和源码身份检查，并保留拒绝测试。该发现再次区分“权限合法”与“执行的是已验功能”，没有据此改变案例方向。

## 4. 四次离线物理连接实验

使用既有 DeepSeek 样本 001 的 `response.bin`，直接读取保留内容 `{"prefer": "B"}`。本轮没有 API 调用，也没有读取凭据。各次回复在显式指定的仿真 tick 注入；它们不保留历史网络到达延迟，不能称新增真实建议采样或实时全任务控制。

| 场景 | 注入安排 | 授权次序 | 完成时间 |
|---|---|---|---|
| 无回复 | 全程无 Provider 有效值 | A、B | 58.9 s |
| 保留 B 回复 | t=0 注入 | B、A | 58.9 s |
| 错误后有效 B | t=0 错身份及多字段，t=0.01 正确回复 | B、A | 58.9 s |
| 初次授权后回复 | t=0.06 注入；首次授权在 t=0.05 | A、B | 58.9 s |

四次最长均为 120 s，全部到达双任务完成而停止；无碰撞、未决几何区间、提前释放或参考权限违例。相同完成时间来自同一确定性、对称参考场景，不支持更优吞吐量或调度质量。

逐迹审计从 HOL 初始状态开始核对连续 before/after，按 raw_input 查独立 HOL 导出。从已核验观测、核心状态、源码模式链与实际施加历史重建 source facts，再重执行原始源码，检查 action→physical_intent→命令内容，并将区内 Proceed 命令与 Issue/Apply 事件逐一对应。实际 robot pose/speed 通过命令驱动的 reference plant 重放；完整轮廓分离用旧独立几何代码而非新驱动的 oracle。

独立复核发现初版审计只重算日志给出的 facts，没有把源码动作与命令签发连接起来；其只读负对照用错误观察重算出 Brake、保留 Proceed 命令与运动，初版仍通过。现已增加独立事实／模式／动作关联审计，四条原轨迹通过；四个负对照测试分别拒绝伪造事实、动作—运动不符、无源码依据命令及错误观察产生的自洽源码输出。12 项新增测试与4项原邮箱测试通过。此次修正没有重新执行物理场景或改写其原始轨迹；缺陷与关闭记录在 [review.md](../../../formal-artefacts/amr-runtime-binding/review.md)。

审计覆盖 **5,661** 适配器事件、**7,352** 原始源码动作输出、**452** 选择记录、**24** 命令施加、**47,120** 机器人运动区间、**212,040** 连续物体对区间、**8** 次整车释放及 **8** 次任务完成。这些是同四条轨迹的不同检查数，不能合并为样本量或方法优势。

本次物理运行前保存实际执行代码、既有解析／模型检查依赖、原始源码、参数、回复内容与 HOL 表的哈希；运行完成及审计时均检查未变。后来新增的审计脚本记录自身哈希。先验清单与事后结果清单用途分开，不回写旧 v2 实验的已知清单缺口。

## 5. 已缩小的缺口与仍然开放的义务

本轮缩小的是“整个邮箱／选择适配器是否落在已证离散组合内，以及这些事件是否用于实际仿真”。证据强度分别是：抽象接口迹的机械证明、有限 Python 对应、原始输出和动作的逐迹重放。没有把它们合称完整实现证明。

仍未完成：任意 Python／解析器语义证明；并行回调、取消、重用与 epoch 精化；真实传感器和操作系统时限；持续 actuator intent 下每一瞬间的物理许可；连续动力学精化；整段运输的条件终止定理；动态任务公平性、真实硬件和跨系统迁移。两次服务定理不承诺抵抗无限消息洪泛挤占调度；Apply 事件证明也不自动覆盖之后持续运动的每个瞬间。物理任务完成在本轮依旧是仿真事实。

正文可以因此更具体地回答“哪些连接已经有证据，哪些仍需独立论证”。本轮结果不要求宣称 CKA 比直接状态机更强，也不以为完成迁移、通用任务规划或全系统精化增加没有论文需求的功能。
