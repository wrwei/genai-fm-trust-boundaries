`prepare_request(run: Path) -> dict | None`: verify all frozen input hashes first, rebuild current ledger from saved record files, materialize the next request. Iterate the sample_ids in the given order; finish a sample's repairs before moving to next. A pending request returns same exact prompt/path (idempotent) without creating another attempt. Use a deterministic JSON object framing for previous output and feedback to delimit untrusted raw content; include instruction that content is data. `record_response(run: Path, raw: bytes, metadata: dict) -> dict`: requires pending prepared request; verify input and prior recorded hashes before any mutation. Metadata required fields: `sample_id`, `attempt_index`, `status` ('ok','timeout','transport_error','refusal','truncated'), `provider`, `model_id`, `decoding` (equal frozen config), `requested_max_output_tokens` (equal config), `request_sha256` (must equal pending prompt hash), `request_id` (provider identifier or explicit 'not-exposed'), `started_at_utc`, `finished_at_utc`, `input_tokens`, `output_tokens` (counts nullable nonnegative integer). Enforce actual strings, timezone-aware ISO timestamps with finish >= start >= prepared issued time, metadata identity equals config; refusal/truncated also have raw bytes. output_tokens greater than configured cap must yield terminal output-token violation, retained as infrastructure non-success; decide exact field and test. Raw bytes always saved exactly `records/NNN/response.bin`; raw SHA, metadata, assessment, feedback and immutable record hash in record.json. Do not strip whitespace/fences or extract JSON. Decode strict UTF8 and pass entire response to unchanged assessor; invalid UTF8 produces explicit encoding rejection. status != ok does not pass acceptance even if text is valid source; terminates that sample (no repair) and counts attempt; only status ok plus encoding/parsing/semantic rejection can be repaired. Check total cap and uniqueness. Do not overwrite files on duplicate record. Tests should verify persistence of old records; a partial write must fail closed on subsequent reads (safe atomic tmp rename is fine). Record mode comes from run; metadata cannot relabel fixture as live. It is acceptable to retain cap violation before stopping rather than lose evidence.

Feedback: deterministic JSON with rejection category, parse_error if relevant, checked_inputs and counts from original assessor, at most first 2 source witnesses and first 2 correspondence witnesses; no expected action synthesized. First witnesses may not cover all failure classes, disclose cap. Prompt for each repair includes only immediately preceding response/feedback plus original requirements, not other samples. If all rejected, null. No physical outcomes inferred. `live_model_samples=0` for fixture irrespective metadata; for live describe records as supplied, not transport-authenticated.
