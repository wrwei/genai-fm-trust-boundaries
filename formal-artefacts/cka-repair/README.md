## 两个基础结果

文件：[Bridge_Algebra_Repair.thy](Bridge_Algebra_Repair.thy)。使用发行版自带HOL的`dioid`，其乘法有序且零为最小元。该类**不要求加法幂等**；不要仅凭同名把它和AFP Kleene Algebra的dioid混同。基础结果在更一般的类中成立，不需要完整CKA实例。

1. **测试收缩：** `t ≤ 1 ⟹ x * t ≤ x`，由 `x * t ≤ x * 1 = x` 得到。
2. **零行为包含：** 对任意二元操作`parallel`和单调映射`project`，`project (parallel P D * 0) ≤ project P`。先化简乘零，再用单调性。无需控制静默、并发交换律或投影保持零。

这两项已在Isabelle2025-2实际构建成功。先用`by fail`观察失败，再加入证明；[初始理论快照](evidence/red-theory.txt)与[初始失败日志](evidence/red-build.txt)保存了失败位置。故意失败用于确认目标确实进入检查，不能用它判断命题真假。

## 原核心结论的八元素反例

可运行脚本：[countermodel.py](countermodel.py)。载体为加法群`Z/3Z`的幂集，共8个元素：

- 选择为集合并，序为包含，代数零为`∅`，单位为`{0}`。
- 顺序和并发乘法均为集合的模3逐元素相加；它们满足所列半环、并发幺半群、分配和交换律。
- 投影由元素映射`0↦0, 1↦0, 2↦1`取像。它单调，而且还保持零、单位和并。
- 取`P=D={1}`，`g={0}`。有`π(D)=1`且`g≤1`，但`π((P∥D)·g)={1}`，`π(P)={0}`，包含关系失败。

脚本穷举检查代数律与投影条件，不只计算一个不验证前提的见证。反例否定的是旧文件**显示出的假设足以推出结论**；旧会话自身是否能解析/构建是另一问题。这里的投影不是事件删除，恰好说明“只写单调公理”和“实际定义为事件删除”不能互相替代。即使补上保持零、单位和并，这个反例仍成立。

一种充分的抽象修复是证明投影兼容并发组合，例如`π(P∥D)=π(P)∥π(D)`，然后结合静默、单位律、收缩与单调性推导。但这只是充分条件，不声称必要或所有语义都满足。不能把目标包含关系本身改名作为公理，随后称已证明组合可靠。

## 具体轨迹语义及核心证明

文件：[Bridge_Trace_Repair.thy](Bridge_Trace_Repair.thy)。最终运行状态与日志列于下方核验记录；只以实际成功构建的版本为已核验结果。

| 对象 | 本批定义 | 边界 |
| --- | --- | --- |
| 行为 | `'e list set`，任意长度的有限事件迹集合 | 没有预设prefix closure或无限执行语义 |
| 顺序组合 | 迹连接的集合提升 | 空语言`{}`是零，`{[]}`是单位 |
| 并发组合 | 归纳定义的交错，保留各分量事件顺序 | 不自动表示同步、共享状态通信或实际调度器 |
| 投影`π_C` | `filter (λe. e∈C)`的集合像 | 实际定义为事件删除，不用投影公理代替 |
| advisory静默 | 每个`d∈D`过滤后为`[]` | 允许`D=∅`；比`π_C(D)={[]}`弱。后者另要求非空 |
| guard `G` | 在当前组合语言上满足`G(P∥D)⊆P∥D`的迹选择器 | 选择器未必在线可实现；状态、因果性和时机另需对应 |

核心义务为：

\[
 (\forall d\in D.\ \operatorname{filter}_C(d)=\epsilon)
 \land G(P\parallel D)\subseteq P\parallel D
 \quad\Longrightarrow\quad
 \pi_C(G(P\parallel D))\subseteq\pi_C(P).
\]

证明先对交错推导归纳：若右边迹无控制事件，交错后删除非控制事件的结果等于左边迹的投影；再提升到语言并应用guard的收缩条件。核心联系在`interleaves_projection`中证明，没有作为额外公理直接假定。

附带结果使几项区别可核查：

- `subidentity_languages`证明在普通迹语言里`T⊆{[]}`只能是`{}`或`{[]}`。因此不能把任意状态guard直接写作这种`T`而不补充状态语义。
- `authority_equality_with_retention`在额外的`P⊆G(P∥D)`前提下得到投影相等。该条件是保留原planner迹的充分条件，比只要求保留投影更强；尚未证明实际guard满足它。
- `represented_completion_retained`仅传递由迹谓词表示的**存在性**完成行为，不证明所有调度下最终完成。
- `planner_is_available`说明`[]∈D`使原planner迹在未过滤的并发语言中可选。这还不能证明guard或调度器选择它们。
- 控制事件泄漏、选择器注入新迹，以及只保留空前缀丢失完成迹的负例，分别显示静默、收缩和进展义务的作用。

这使CKA方向有了一个可检查的语义起点，但不是完整CKA库实例证明，也不提供从旧Python状态机、Java提取器或真实执行器到该语言模型的精化证明。包含界只有在planner本身满足相应安全性质且实现对应成立时，才能支持进一步的系统安全论证。

## 下一项研究应检验什么

1. 固定一个有限状态运行时接口：planner请求、advisory事件、guard判断、外部提交和失败恢复，明确唯一能发出控制效果的路径。证明该操作语义产生的迹满足已核验的静默/收缩条件；处理检查后到执行前的状态变化和未建模副作用。
2. 选定进展性质，例如“在明确的调度公平和有限服务延迟前提下，已获grant的请求最终进入/退出”；区分存在完成路径与所有合适执行最终完成。先找最小反例，再证明条件。
3. 将这些实际前提和结果挂入证据记录：制品与版本、语义、假设、状态、证明/日志及依赖。环境或实现变更使哪些结论失效必须可追溯；候选记录schema本身不证明其内容真实。

先完成一个这样的模型—执行接口，再用独立案例检验可迁移性，比仅扩大case study数量更直接检验当前缺口。是否采用完整AFP CKA接口，由实际所需的组合与迭代规律决定；当前证明没有借用未实例化的库名增强结论。
