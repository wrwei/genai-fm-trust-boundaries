# AMR advisory v2 finite protocol

`AMR_Protocol.thy` defines the two-robot executable core, an independent permissive safety reference, and distinct trusted/provider event constructors. See `interface.md` for the frozen Python vocabulary.

## Targets and exact scope

- `step_simulation` and `finite_word_simulation`: current-state guarded core actions refine the independent reference for every initial core state and arbitrary finite input word. Reference events retain Register and Observe. Clear is a supplied trusted fact; its geometry is outside HOL.
- `system_decomposition`, `operational_embedding`: actual operational `system_next` runs split into trusted `open_next` runs and provider-only events, and satisfy independently defined causal mailbox transitions. Hidden Validate and Service belong to the trusted component. `K_T` checks request/first-reply/consumption state, not a safety predicate.
- `component_authority`: instantiates existing `authority_boundary_traces` with independently defined `P_open`, provider language `D`, and `G_T X = X intersect K_T`. `open_authority` proves the independent reference bound; `system_authority` combines both. This is an operational component decomposition, not projection of the whole system relabeled as a planner.
- `conditional_authorization_progress`: from an empty pending choice with an effective legal request, a Service supplied with the total legal selector validates a choice; any finite sequence of advice traffic/consumption/request events or usable same-permission observations preserves it; the next Service grants regardless of its intent argument. This gives authorization under supplied trusted service, without an advice-reply assumption. Permission must remain usable until Grant and requests/owner are unchanged by the allowed intervening events. It is a bounded finite-word progress theorem, not an infinite-run fairness formalization or transport-completion theorem.
- `wait_forever`: every natural iteration of the faulty wait-for-advice service remains in the same state with advice=None. Its empty finite visible prefixes satisfy the reference. This expresses an infinite constant-run witness using all natural finite prefixes.
- `e3a/e3a_fault`, `e3b/e3b_fault`: separate finite rejection/fault witnesses for Validate→Block→Commit and Issue→Block→Apply. Observe preserves saved intent/command; only the respective current-state check prevents the bad result.
- `selector_total_legal`, `advice_witnesses`: independent F chooses valid advisory A/B or fixed A-first fallback, with legal totality. Original generated source bytes are checked externally by the parent source audit; no Python source theorem is asserted here.

The broad trusted core and `S_HOL` deliberately accept arbitrary type-correct candidate intent for safety. The separate operational `source_next`/`S_source` restrict empty-pending Service/Validate intent to F(core,mailbox); this operation is the actual atomic selection latch. Consume is optional read-only bookkeeping. `source_inclusion` embeds every source-restricted run into the broad model, and `source_authority` transfers its safety bound. `source_latch_binding` and `source_latch_choice` connect the actual accepted transition to the persistent mailbox-derived choice; `source_advice_response` and `source_fifo_response` establish local R-F. `source_service_effect` identifies every accepted source Service with the F-driven service transition. `validated_choice_frozen` and `source_provider_preserves_pending` show that later advice cannot overwrite a pending choice.

`authorization_from_any_pending` strengthens the earlier two-service result: from ANY pending field, if an effective request is legal, at most three supplied Service opportunities produce Grant. Each opportunity uses F with an independently universally quantified advice value (including permanent None), with arbitrary finite benign gaps before/between services. If pending is valid, the first Service grants; if empty, at most two; if stale/invalid, the first clears it and at most two more grant. `grants_within` stops at the first Grant, so the premise never demands a free owner or authorization stability after Grant. Its finite service/gap pattern is a bounded scheduling condition, not an infinite-run fairness theorem. Combined with `source_service_effect`, the opportunities are the accepted source-driven Service transition; arbitrary interleavings beyond the declared benign class are outside this progress statement.

The fixed-mission mailbox now retains the first reply across Consume events, matching the concrete persistence rule; `persistent_consume` and `repeated_consume` check repeated reads. One Boolean abstracts registered identity; typed Reply abstracts external parsing/binding. No unbounded identity/mission refinement or exhaustive mailbox/system conformance is asserted. Core exports exclude mailbox. Mission cancellation, reservation-generation reuse, distributed propagation, continuous motion, Clear geometry, real halted/completed states and physical completion remain outside these theorems. Apply synchronously reads current trusted state in the local event model. The one-task-per-robot experiment registers each once; the abstract core allows repeated Register and fixed A-before-B fallback, not general arrival FIFO. Original source certification and core/selector conformance remain finite external checks, not a HOL proof of the Python interpreter or source bytes.

## Reproduction and evidence

Run from the repository root:

```
python formal-artefacts/amr-advisory-v2/hol/build.py
```

This uses pinned Isabelle2025-2 and USER_HOME under `<ISABELLE_WORKDIR>/`. The actual parent session is `Bridge_Algebra_Repair`; `Bridge_Trace_Repair` is its imported theory. `build.log` records the build. The ML audit rejects skipped-proof or oracle dependencies of all headline results. Exports are generated by Isabelle's HOL code evaluator from the checked definitions, not by the Python simulator.

CSV order: 432 states (req_a,req_b,owner,blocked,fresh,pending,command nested in that order; bool false/true, optional robot null/A/B) × 27 inputs (the order of `all_inputs`). Each row has initial 7 state integers, next 7, then 3 event integers. Optional robots encode null/A/B=0/1/2; booleans=0/1; event tags 0=None,1=Registered,2=Observed,3=Grant,4=Issued,5=Proceed,6=Released; event arguments are robot,0 except Observed(blocked,fresh). `interface.md` describes behavior. Independent Python checking must enumerate the same domain and compare every row; these finite checks do not prove arbitrary Python-run refinement.
