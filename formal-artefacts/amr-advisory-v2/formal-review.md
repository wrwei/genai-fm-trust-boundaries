## Resolution of the initial review and retained boundaries

1. **Bounded progress strengthened and operationally connected.** `authorization_from_any_pending` quantifies over any starting pending field, three arbitrary advice values, and three arbitrary finite benign gaps. A valid pending choice grants at the first opportunity; an empty pending choice takes at most two; an invalid pending choice is cleared before at most two further opportunities. `grants_within` stops at the first Grant, so the free-owner premise is not imposed after Grant. The proof uses legal-selector totality and benign preservation, not an assumption of eventual success. `source_service_effect` identifies each accepted source-machine Service with exactly the F-driven core transition used by this theorem. Thus the local operational link requested in the initial review is now present. The theorem remains a finite Service/gap pattern: it does not quantify over unrestricted source-machine traces or formalize an infinite fairness scheduler. The defined gaps contain advice, request/consume bookkeeping and usable same-permission observations; arbitrary Register/Commit/Issue/Apply interleavings are not covered. Under that declared scheduling scope this is an adequate minimum authorization-progress result, including perpetual absence of advice.

2. **Atomic selection latch now has the required functional binding.** `source_next` restricts accepted Service/Validate at empty pending to `select s (slot m)`. `source_latch_binding` proves that accepted transition reads the current slot, uses the same intent for validation, and preserves the mailbox; `source_latch_choice` proves that an available request becomes the selected pending choice. `source_advice_response` and `source_fifo_response` express the local R-F clauses, while selector totality covers the available-choice condition. `validated_choice_frozen` and `source_provider_preserves_pending` prevent later advice from replacing a pending choice. Service/Validate itself is the atomic latch; Consume is explicitly read-only bookkeeping, so there is no separate unbound latch value. The previous A-mailbox/B-choice example remains permitted in deliberately broad `S_HOL`, but is rejected by `S_source`. `source_inclusion` and `source_authority` correctly transfer broad safety to this restriction without weakening the independent reference.

3. **Persistent consumption mismatch fixed.** `causal_next` now returns the unchanged mailbox on matching Consume. The first accepted reply remains in the slot and later provider replies cannot overwrite it. `persistent_consume` and `repeated_consume` cover arbitrary repeated reads; the earlier consecutive-latch counterexample no longer applies. The initial clearing model was not an automatic overapproximation under the obvious event mapping, and the revision correctly replaces it rather than defending that claim. This closes the concrete persistence mismatch. It does not prove full Python mailbox/system refinement: request identity, external parsing, context changes and implementation event mapping remain outside the finite core exports, as the revised README states.

No load-bearing defect remains in the stated finite authorization profile. The residual limits are explicit scope boundaries, not discharged implementation or physical obligations.
